# 캐시지기 · 암시적 캐시 최적화 (RisuAI 플러그인)

모델에 보내는 요청을 **"지난번 요청 + 뒤에만 덧붙임"** 모양으로 정리해서, Claude·Gemini·OpenAI·DeepSeek의 프롬프트 캐시가 대화 대부분을 다시 쓰게 만듭니다. 실제 채팅 기록은 건드리지 않고 보내는 요청만 바꿉니다.

## 설치

1. [cache-jigi.js](https://github.com/happydesk213124/cache-jigi/raw/main/cache-jigi.js)를 내려받고, RisuAI → 설정 → 플러그인 → 플러그인 추가에서 고릅니다.
2. "요청을 바꿀 권한" 창이 뜨면 허용합니다.
3. 끝. 기본 모드(최대)로 바로 동작합니다.

설정 화면은 Risu 설정의 **캐시지기** 항목이나 햄버거 메뉴의 **⚡ 캐시지기**로 엽니다.

## 하는 일

| 문제 | 캐시지기가 하는 일 |
| --- | --- |
| 컨텍스트가 차면 오래된 대화가 매 턴 하나씩 잘림 | 가끔 한 번에 크게(기본 40%) 정리하고 시작점을 고정 |
| 시스템 프롬프트의 시간·변수 줄이 매 턴 바뀜 | 바뀌는 줄만 찾아 꼬리로 옮기고, 제자리엔 늘 같은 표시 |
| 긴 규칙·로어북이 대화 기록과 마지막 입력 사이에 있음 (매 턴 새 대화에 밀려 통째로 제값) | 1,000자가 넘는 글은 대화 앞으로 옮겨 고정. 짧은 머리글·지시는 제자리 |
| 긴 프롬프트 안의 여러 줄이 매 턴 바뀜 | 바뀌는 부분만 꼬리로 옮기고 나머지 줄은 그대로 고정 |
| 로어북이 켜졌다 꺼졌다 함 | 새 항목은 2턴 같으면 그 턴 자리에 고정(장부). 꺼지거나 내용이 바뀐 항목은 다음 정리 때 뺌 |
| 요약(HypaV3 등)이 매번 다르게 뽑힘 | 자꾸 바뀌는 항목으로 배워서 꼬리로 |
| 정규식이 옛 메시지 글자를 바꿈 (상태창 숨기기 등) | 처음 보낸 글자를 유지하고, 정리 턴에 한 번에 반영. 직접 고친 메시지는 바로 반영 |
| 요청이 실패해서 Risu가 자동으로 다시 보냄 | 첫 시도와 똑같은 요청을 다시 보냄 (새 턴으로 치지 않음) |
| Claude는 캐시 지점이 있어야 캐시함 | 설정의 "Claude 캐시 지점"을 **자동**으로 바꾸면 머리 끝·지난 턴 끝·이번 턴 끝에 지점(최대 3개). 기본은 꺼짐 (오픈라우터 Gemini에서는 이 지점이 암시적 캐시를 방해할 수 있어서) |
| 캐시가 진짜 됐는지 모름 | 화면의 **실제 캐시 확인**: Risu 요청 기록에서 진짜 캐시 토큰을 읽어 보여 줌 |

## 실제 캐시 확인

화면에서 **실제 캐시 확인**을 누르면 Risu의 요청 기록(최근 20개)에서 이 채팅의 요청을 찾아 두 가지를 보여 줍니다.

- **실제 캐시**: 모델이 응답에 적어 준 캐시 토큰 ÷ 입력 토큰
- **앞부분 일치**: 바로 전 요청과 앞에서부터 똑같은 글의 비율 (여기까지 캐시될 수 있음)

앞부분은 잘 맞는데 실제 캐시가 낮으면 모델 쪽 사정(캐시 유지 시간, 키 여러 개, 4,096토큰 미만 등)이고, 앞부분 자체가 안 맞으면 "진단 내용"에 달라진 곳이 나옵니다. 처음 누를 때 Risu가 요청 기록 읽기 권한을 묻습니다. 포켓리스는 설정 → 시스템 → 리퀘스트 로그에서 기록이 켜져 있어야 합니다(기본값 켜짐).

## 모드

- **안전**: 대화 자르기와 캐시 지점만. 프롬프트 순서는 그대로라서, 매 턴 바뀌는 글이 있으면 효과가 작습니다. 포켓리스 프리셋에서는 권하지 않습니다.
- **균형**: 매번 바뀌는 것만 뒤로 보내고 나머지는 고정. 대화 기록과 마지막 입력 사이에 낀 긴 프리셋 글은 대화 앞으로 옮김.
- **최대 (기본)**: 대화 사이 삽입(작가 노트 등)까지 뒤로. 4,000자가 넘는 긴 삽입은 꼬리 대신 장부에 고정. 캐시는 가장 좋지만 지시 위치가 바뀜.

"지금 정리하기"는 꺼진 로어북과 밀린 변경을 다음 요청에 바로 반영합니다. 대화는 지우지 않고, 캐시는 그 턴에 한 번 깨집니다.

## 다른 플러그인과 함께

- 항상 다른 플러그인이 요청을 다 바꾼 **뒤에** 정리합니다. 요청마다 "맨 뒤 처리기"를 목록 끝에 다시 붙이고, 그게 안 되는 환경이면 두 번 놓친 뒤 제자리에서 처리합니다.
- **Risu64**: 같이 써도 됩니다.
- **Provider Manager**: 같이 써도 됩니다. Claude 캐시 지점은 PM의 캐시 설정이 최종으로 정합니다.
- **명시적 프롬프트 캐시** 플러그인을 쓰면 설정의 "Claude 캐시 지점"을 **그대로 두기**로 바꾸세요.
- **Omni Nexus**: 같이 써도 됩니다. 스트리밍 태그 규칙은 앞쪽에 고정돼 캐시되고, 태거 보조 호출은 건드리지 않으며, 이미지 저장으로 옛 답장의 빈칸만 달라져도 캐시를 지킵니다.
- **Gemini 4**: 명시적 캐시가 없어서 암시적 캐시만 씁니다. 스트리밍을 켜도 요청 내용은 같습니다.
- **포켓리스(PocketRisu)**: 같이 써도 됩니다. 모델 프리셋은 system 글을 전부 맨 앞으로 올리기 때문에, 캐시지기는 고정 부분 밖의 글을 `system:` 표시가 붙은 user 메시지로 보내고 옆 user 메시지에 합칩니다. 맨 위 숫자는 예상치이고, 진짜 값은 "실제 캐시 확인"으로 봅니다.

## 업데이트

플러그인 파일 맨 위에 이 저장소 주소가 적혀 있어서, Risu가 새 버전이 나오면 플러그인 설정에서 알려 줍니다. 눌러서 바로 업데이트하면 됩니다. 업데이트 뒤에는 권한 창이 다시 뜰 수 있으니 허용해 주세요.

## 시험 (개발용)

```bash
node test/sim.mjs --budget=2500 --turns=80
```

Risu처럼 프롬프트를 조립해 여러 턴을 돌리고, 연속 요청의 앞부분이 얼마나 같은지 비교합니다. 요청을 보내는 흐름(재시도 포함)과 Gemini 본문 변환은 Risu·포켓리스 원본 코드를 옮긴 것입니다.

옵션: `--mode=safe|balanced|max`, `--obf=1|2`(단어 바꾸기 플러그인), `--memory=1`(무작위 요약), `--notime=1`, `--long=1`, `--omni=1|2`(Omni Nexus), `--omnibig=1`, `--varlore=1`(값이 바뀌는 로어북), `--btn=1`(지금 정리하기), `--varpost=1`(맨 뒤 지시문이 바뀜), `--conv=risu|pm|pocket`(Gemini 본문 변환), `--retry=0.2`(요청 실패 후 재시도 비율), `--bighead=1`(긴 메인 프롬프트), `--block=1`(프롬프트 안 여러 줄이 매 턴 바뀜), `--merged=1`(system 글이 하나로 합쳐짐), `--biglore=1`(긴 로어북 여러 개), `--reload=10`(새로고침), `--notail=1`(맨 뒤 처리기가 안 되는 환경), `--migrate=1`(예전 버전 상태에서 이어 감), `--trail=1`(긴 규칙·로어북이 대화와 마지막 입력 사이에 있는 프리셋), `--rows=1`, `--events=1`, `--dump=1`, `--report=1`.

결과의 "Gemini 4 규칙 적용" 줄은 실제 본문 모양과 4,096·2,050토큰 규칙을 반영한 값이라 예산이 충분히 클 때(`--budget=120000 --turns=320 --long=1`) 봅니다.

화면 시험: `node test/serve.mjs` 후 `http://localhost:5178/test/ui.html` (주소 끝에 `?real=good|google|bad|short|denied`)
